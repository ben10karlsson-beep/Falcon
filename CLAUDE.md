# Falcon

A poker study app for understanding the math and strategy of No-Limit Hold'em, pre and post flop. Built for the owner to learn with, and now public (see Deployment). The goal is understanding, not just memorizing: every tool should explain *why*, in plain language.

## How to run

- Open `index.html` in a browser. No build step, no dependencies, no framework. Keep it that way unless there is a strong reason.
- All tests: `node tests/run-all.js` (must stay green). It runs `tests/engine.test.js` (evaluator, equity) and `tests/ranges.test.js` (range parser plus the range audit below).
- Hooks run the tests automatically: a Claude Code PostToolUse hook (`.claude/settings.json` → `.claude/hooks/test-on-edit.js`) after edits to `js/engine.js`, `js/ranges.js` or `tests/`, and a git pre-commit hook in `.githooks/`. Enable the git hook once per clone: `git config core.hooksPath .githooks`.

## Deployment

- Live at https://ben10karlsson-beep.github.io/Falcon/ via GitHub Pages (branch `main`, root). Every push to `main` redeploys in a minute or two. `.nojekyll` makes Pages serve files as-is.
- Pages is case-sensitive (Windows isn't): asset paths in `index.html` must match file names exactly.
- Analytics: GoatCounter (site code `falcon`, dashboard https://falcon.goatcounter.com), no cookies. A snippet before `</body>` counts each hash route (`#trainer/read`, `#theory/...`) as its own page.
- Link previews: `og.png` (1200×630) in the repo root, referenced by absolute URL in the Open Graph / Twitter tags. It shows the real BTN opening range; if the BTN chart changes, regenerate it (an HTML template that loads engine.js + ranges.js, screenshotted with headless Chrome at 1200×630).
- The footer under every view states that charts are approximations and figures are computed by the engine. Keep it true.

## Layout

```
index.html        page shell + markup for every view (tabs: Preflop ranges, Trainer, Postflop, Theory, Resources)
css/falcon.css    all styles; colors are CSS variables on :root
js/engine.js      card encoding, 5–7 card evaluator, equity (exact + Monte Carlo), flop classification, board texture. UMD: window.Engine in browser, module.exports in Node
js/ranges.js      preflop range data (RFI, VS, V3 = facing a 3-bet), range-string parser, shared helpers (getRange, freqs, handAt, pct, combos, rangeOptions, rangeSize)
js/preflop.js     range grid view + preflop hands trainer (incl. "My leaks" mode, stats in localStorage)
js/reading.js     Read ranges trainer: paint a range on the grid (opens, calls, 3-bets, calling a 3-bet), graded against the chart in combos, plus the flop step (equity vs your range vs the chart range) (window.Reading)
js/solved.js      solved BTN vs BB flops (generated by solver/export.js, do not edit; window.Solved / module.exports)
js/solved-combos.js  BTN's strategy per combo on those flops, for the c-bet trainer (generated by solver/export.js, ~100 KB, loaded on first use; window.SolvedCombos)
js/postflop.js    equity calculator + board explorer with turn and river (Postflop tab); Hand vs hand quiz, range trainer and c-bet trainer (Trainer tab) (window.Postflop)
js/theory.js      theory chapter routing (window.Theory) + calculators (pot odds, outs, matchups, combo drill, hand vs range, EV, seat bars)
js/opfield.js     living layer (Op Field): grid lens, gutter dot field, grade ripples and the right-answer pop, plus the effects and dots switches; loaded after app.js
PRODUCT.md        product truth (users, purpose, constraints) for design work
DESIGN.md         the Op Field design system (tokens, components, motion, themes); .impeccable/design.json is its token sidecar
archive/          previous designs kept for reuse (archive/warm-charcoal/)
js/app.js         tab routing + Trainer modes (address hash: #trainer[/read|quiz|range|cbet], #postflop, #theory/<chapter>), data-go practice buttons, keyboard shortcuts; loaded last
tests/            engine, range and solved-data tests; run-all.js runs them all
solver/           offline postflop solving (not loaded by the site): make-config.js turns the BTN open + BB flat charts into a TexasSolver config, summarize.js reads a flop dump, flops.js lists the 30 solved flops, batch.js solves them all (resumable, retries TexasSolver's occasional startup crash), overview.js prints a table, export.js writes js/solved.js and js/solved-combos.js. TexasSolver v0.2.0 (Windows release, unzipped into solver/TexasSolver/) and solver/work/ are gitignored. Units are tenths of a bb (pot 55 = 5.5bb, stack 975); one flop takes 2–7 min (12 threads) to reach ~0.5% exploitability
og.png            link preview image (see Deployment)
```

Scripts are plain globals loaded in order: engine → ranges → preflop → reading → theory → solved → postflop → app → opfield. A small inline script in <head> sets the theme, effects and dots flags before first paint.

Tabs: **Trainer** holds every graded trainer (Preflop hands, Read ranges, Hand vs hand, Range trainer, C-bet); **Postflop** holds the tools (equity calculator, board explorer). Theory "Practice this" buttons use `data-go="train:<mode>[:<sub>]"` or `"postflop:<calc|board>"`.

## Design language

The current design is **"Op Field"**: a living 1960s op-art field (Vasarely, Bridget Riley). DESIGN.md (with its token sidecar `.impeccable/design.json`) is the full record; this section is the summary and the rules that win.

Design skills (`design-taste-frontend` in `.agents/skills/`, symlinked into `.claude/skills/`; the impeccable and frontend-design plugins) are welcome, but this file wins on any conflict: no build step or dependencies (no Tailwind, component libraries or npm installs), keep the Op Field tokens, fonts and grid encoding below, and the copy rules further down. Direction contract: `.impeccable/surfaces/index-html.md`; product truth: `PRODUCT.md`.

- Light: op-white ground `--bg #eef0f5`, white plates `--surface #fbfbfd`, ink `--ink #15161d`, ultramarine `--ultra #2430d8` (calls, structure), magenta `--magenta #d8226a` (raises), grade colours `--good`/`--warn` for grading only. Dark ("Op Field at night", `data-theme="dark"` on `<html>`): ground `#0f1120`, plates `#171a2c`, ink `#eceef6`, ultramarine `#5361ff`, magenta `#e8357f`. Every colour goes through tokens so both themes work; `--ink` is the strongest foreground in both.
- Three switches in the app bar, each saved in localStorage and applied in `<head>` before first paint: theme (`falcon-theme`, first visit follows the system), effects (`falcon-fx`, `data-fx`) and margin dots (`falcon-dots`, `data-dots`).
- Sharp corners everywhere; circles are the only curves (playing cards keep a 4px corner). Panels are flat plates separated by tone and a hairline (`--hair`); no cast shadows, no glows, no gradients as decoration.
- The range grid: each square is a plastic unit, a disc whose **area** is the frequency (`setUnit` in ranges.js: radius = sqrt(share)). Magenta core for raise, ultramarine ring for call, a bare square for fold. The label is drawn twice (ink, plus a white copy clipped to the disc) so it inverts exactly at the disc's edge. The selected hand gets an ink frame drawn inside its square.
- Controls are ghosts until chosen, then struck in solid ink (tabs, chips, segmented rails with one ink block that slides to the choice). Selection is always ink, never a separate highlight colour.
- Type: Anybody (wide, heavy) for display; Hanken Grotesk for reading, numbers via tabular figures (`--mono` points at it). Labels are sentence case, no letter-spacing, no ALL-CAPS.
- Living layer (`js/opfield.js`): the grid lens (discs swell toward the pointer, capped at the square's edge), the gutter dot field (pointer only counts inside the gutters, eased), a ripple in the grade colour and a small "pop" on the pressed button for correct answers. Trainer tables carry a plain, still two-row ink checkerboard along the top. Effects pause with the switch and under reduced motion.
- Text colours keep ≥ 4.5:1 contrast on `--bg` and `--surface` in both themes; `--dim` is for non-essential hints only.
- Must work at phone width (~390px) with no horizontal page scroll (the grid switches to fluid columns at ≤420px).

**Previous design ("warm charcoal" with "card room" controls)** is archived: the stylesheet is in `archive/warm-charcoal/falcon.css` (see the README there) and the complete site in that design is the git tag `design-warm-charcoal` (`git checkout design-warm-charcoal -- index.html css js` restores it).

## Poker conventions and decisions

- Format: 6-max cash, 100bb, opens 2.5bb (SB 3bb), 3-bets ~11bb OOP / 7.5bb IP, 4-bets ~25bb vs 11bb / ~20bb vs 7.5bb (`threeBetSize`, `fourBetSize` in ranges.js).
- Facing-a-3-bet charts (V3): frequencies are conditional on having opened the hand, so only hands in the opener’s RFI range appear; call + 4-bet ≤ 100%. Audited in tests: the opener continues 40–65% of its opening range and 4-bets 5–15%, AA/KK always continue, bigger pairs never continue less. The range an opener brings to a 3-bet pot is open frequency × call frequency (`call3:` options in rangeOptions).
- Preflop ranges are hand-built approximations shaped like solver output, NOT exact solver data, and the UI says so. They were audited for: later seats ⊇ earlier seats, monotonic kicker/pair order, and sizes near published benchmarks (open ≈ UTG 17%, HJ 21%, CO 29%, BTN 45%, SB 41%; BB defends ~52% vs BTN). `tests/ranges.test.js` checks all of this automatically (one deliberate exception: A5 may be opened more than A6–A9, as solvers often do).
- Range strings: `"55+, A2s+, KTs-K8s, AJo:0.5"` — `:x` is a frequency 0..1.
- Read ranges grading: overlap = combos in both ÷ combos in either (`rangeOverlap` in ranges.js); a hand the chart plays at frequency f counts f in and 1−f out, so mixed hands give partial credit. 85%+ is "spot on".
- Trainer grading: action is "correct" if the chart takes it ≥25% of the time, "inaccurate" if >0%, else "mistake".
- Outs shown to the user are clean outs only; cards that improve hero but still lose are shown separately as "tainted outs".
- Board explorer tips are general solver tendencies, labelled as such — never present them as a solved strategy. The exception is BTN opens, BB calls: that spot shows real solver output from js/solved.js (exact flop up to suit relabelling, or the closest solved flop by texture, labelled as such). Its sizes are check / 33% / 75% for BTN and call / check-raise / fold for BB; the "why" text is generated from the numbers, so keep it consistent with them. Solver data covers the flop only; on the turn and river the explorer shows range equity, hand types and what the new card changed, from the full preflop ranges (labelled as such), plus a next-card map.
- C-bet trainer: BTN vs BB, BB checks, bet or check, graded per combo against js/solved-combos.js. Only bet vs check is graded (correct ≥25%, inaccurate ≥5%); the size is named only when the solver puts ≥80% of its bets on one size, because the two sizes are often close in value.

## Theory page structure

The Theory tab is a learning path of chapters, one on screen at a time: 1 Equity → 2 Outs → 3 Pot odds and EV (against one hand), then 4 Combos and blockers → 5 Equity vs a range → 6 Calling vs a range (the same ideas against a range), then 7 Ranges and strategy, plus a Glossary. Each chapter is a `<section class="chapter" data-ch="...">` with a "Builds on" line, a Recap, a "Practice this" block (`data-go="view:sub:mode"` buttons into the trainers) and a pager filled by theory.js.

- A chapter may only rely on ideas from earlier chapters. Put new theory content in the first chapter where its prerequisites are covered, and link back with `data-ch` links instead of "above/below".
- One pot odds notation everywhere: "the pot" includes the bet you face, and equity needed = call ÷ (pot + call). The bet ÷ (pot before the bet + 2 × bet) form is only shown as a shortcut.

## Writing style for UI copy

Plain, direct sentences. Name things the way players do (3-bet, c-bet, outs). Explain the reason behind every recommendation. No hype.

Every number in UI copy (equities, combo counts, pot odds, range sizes) must be computed with the engine or worked out step by step, never written from memory. Hardcoded figures in theory examples come from running `js/engine.js` with a high sample count, and should match what the in-page calculators show.

## Ideas / roadmap

Done: BTN vs BB single-raised pots are solved over 30 representative flops (solver/, js/solved.js) and shown in the board explorer; the c-bet trainer grades single hands on that data (js/solved-combos.js); the board explorer takes a turn and river. Preflop solver data is much harder (needs a paid preflop solver such as MonkerSolver); keep the hand-built charts, labelled as approximations. Check GoatCounter for which trainers get used before choosing.

- More solved spots (CO vs BB, SB vs BB, 3-bet pots) with the solver/ pipeline, and in the c-bet trainer. Turn solving would need the turn nodes dumped (the current dumps stop at the flop).
- More formats: other stack depths, tournaments.
- Range trainer, next steps (live: guess flop equity vs the chart range; call-or-fold vs a flop bet; Read ranges, paint a range and compare it in combos, then play a flop to see your equity vs your painted range against the chart range): add flop betting so ranges narrow (c-bet / call), which would also make call-or-fold more realistic.
